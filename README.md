# 无限融合变异捕鱼

几乎完全通过 QQ 群指令游玩的捕鱼小游戏。公共鱼群、金币和经验沿用捕鱼的思路；鱼种由群友贡献推动原创变异，逐代形成族谱。

完整讨论整理见 [游戏设计文档](docs/game-design.md)。文档中的已定规则和待定数值分开记录。

## 当前状态

已实现普通／Fever 捕获、金币经验升级、每日投饵、自动刷新、变异贡献及满刻度任务的 Redis 持久化，刷鱼与结算使用 LXGW WenKai 字体的 WebP 图片。已接入商店、背包、单抽／十连／百连、渔具／工具两槽装备、三档食料／强化剂／加成卡。满刻度任务由独立定时任务读取群友头像提色，调用宿主已配置的 DeepSeek 生成新鱼名和描述，成功后新鱼加入该群鱼池，并在群里发送诞生卡片（新鱼图、名字描述、亲代、两位贡献者及其提供的颜色、难度与收益）。

2026-09-28 用户明确授权向 DeepSeek 发送贡献前两名的名片／昵称、头像提取色值及亲代设定；不发送 QQ 号、群号或头像原图。生成失败保留任务，指数退避重试；重启可恢复超时任务。头像读取失败时使用亲代对应色位作为备用色，并在子代快照标记 `color_fallback`。

暂不配置远程地址；本地仓库不等于已配置可递归克隆的 Git submodule，后续确定远程后再补 `.gitmodules`。

## 宿主接入

- 目录：`src/infinite-mutation-fishing`，包：`infinite_mutation_fishing`。
- 主仓 `src/quart.py` 将子仓 `src/` 加入包搜索路径并安装 Web Blueprint。
- 主仓 `bot.py` 加载 `infinite_mutation_fishing.qq.mutation_fishing`。入口末段保持唯一，避免与红叶镇的 `plugin` 注册名冲突。
- 健康检查：`GET http://localhost:8000/web/api/infinite-mutation-fishing/health`，当前 `stage: capture`。
- QQ 插件名：`无限融合变异捕鱼`，沿用宿主插件管理，默认关闭；在目标群启用后可使用下述命令。
- 使用适配器无关的命令回复；群身份兼容宿主当前 Milky、QQ 官方群事件及 OneBot 的 `group_id`。私聊不触发游戏命令。
- 当前不提供 Web 玩家页面，因此无需前端构建。

## 捕获指令与运行规则

| 群指令 | 作用 |
| --- | --- |
| `捕鱼` | 尝试捕获当前鱼，成功／失败均以 WebP 展示实际奖励 |
| `鱼塘` | 当前鱼、个人等级金币、投饵量、待生成任务 |
| `族谱` | 回复本群鱼族谱网页链接 |
| `状态` / `池子状态` / `完整状态` | 图片展示自己生效中的强化剂与加成卡／鱼塘（平均渔力、投饵、鱼群、当前鱼、食料、待诞生鱼种）／两者合并并列出每种鱼每次刷新的出现概率 |
| `商店` / `商店购买 编号或名称` | 查看或购买四档渔具及普通、白银食料 |
| `面板` | 查看个人头像、等级经验、金币、渔力、变异力、装备与图鉴 |
| `背包 [页数]` / `使用 编号或名称` | 每页十件，按编号排序；重复使用已装备物品卸下 |
| `强制使用 编号或名称` | 覆盖当前食料；每次消耗一件，全群每天最多 2 份 |
| `签到` | 每天一次，必定捕获一条鱼，金币经验与变异进度按倍数结算 |
| `单抽` / `十连` / `百连` | 10/100/1000 金币获得 1/11/110 件道具 |
| `刷鱼` | 超级管理员测试：当前无鱼时立即刷新一条 |
| `fever` / `鱼群` | 超级管理员测试：当前无鱼时启动 Fever 并立即刷新 |

指令直接使用无前缀名称；不额外处理旧捕鱼指令冲突，由群管理员保证两个插件不会同时启用。

保留原版的无技能核心：成功率基准 60%，依渔力与标准难度的差值使用原版指数公式；正常渔力为等级加渔具、工具和强化剂，Fever 等级渔力为等级整除 5、渔具渔力减半，工具与强化剂不变。成功获得鱼种配置的金币与经验，失败获 1 经验。等级公式沿用旧捕鱼。技能、会心、建筑、工坊和神秘商店不在本轮迁移范围。

2026-09-28 防肝调整后，所有鱼都按原 Fever 规则捕获：每人每次刷新尝试一次，捕获后鱼保留，失败不逃跑（`flee` 配置保留但不再使用）。普通鱼停留 5 分钟、渔力不削弱；Fever 每轮 2 分钟、出鱼更密、等级渔力按五分之一、渔具渔力减半，到期清除剩余鱼群。Fever 开始时发送旧版文字「大量的鱼群聚集了起来！…」，整段 Fever 结束时发送一次「鱼群散去了！」。

每分钟尝试刷新，凌晨 1:00～8:00 不刷。19:30 后该小时内首次定时任务按「当天投饵量 ÷ 每日上限」判定 Fever（上限 2 份，投满必定），持续随机 60～120 分钟。普通饵料提高 R 权重 30 分钟；Fever 沿用旧版 R/SR/SSR 饵料加成。新增参数统一在 `data/capture-settings.json`，各档基础总出率 R/SR/SSR=1%/0.2%/0.05%；普通祖先鱼难度 0、收益 10 来自旧版第一种基础鱼。新鱼基础难度 R/SR/SSR 为 0/30/100，再加变异触发时前两位贡献者的平均等级，生成延迟期间升级不会改变快照。

每次刷新最多一次有效变异贡献：按 0%／1%／5% 亲缘规则，乘变异力系数，再乘 0.85～1.0 的随机浮动（步长 0.001），最后按剩余刻度截断，向下保留三位小数。若本轮只有一位贡献者，最多到 99%；卡在 99% 时实际 0% 不占本轮机会，第二位可继续贡献。

实际刻度决定排名，并列先随机打乱再稳定按贡献排序；满刻度冻结前两名和历史账本，进度归零，创建持久化子代生成任务。同一亲代生成期间不再增加贡献，避免新子代关联限制未生效时提前计分。

鱼种、玩家和族谱当前按群隔离，使用独立 Redis 键 `mutation_fishing:v1:group:<group>`。WATCH/MULTI 原子保存当前鱼、玩家奖励及贡献，消息编号去重保留一天，重启保留当前轮尝试记录。群推送只在宿主启用此插件的群发送；故障导致刷鱼图未发送时后续定时任务会重试。

## 商店、面板、背包与抽卡卡片

`panels.py` 与刷鱼／捕鱼结算卡共用 `visuals.py` 的字体、标题区和配色：浅绿背景上的无边框白色圆角卡片，稀有度用浅色底的编号徽章区分，不再使用描边。四张卡片宽度统一 800，高度随内容增长，底部给出下一步指令提示。

- 商店：每行三张商品卡，显示编号、名称、属性、描述（最多三行）和金币价格。
- 背包：两列、每页十件，按编号排序；已装备物品显示「已装备」标签。页码小于 1 取 1，超出末页取末页，非数字提示“页数必须是数字”。
- 面板：头像（圆形，读取失败时显示名字首字）、等级经验条、渔力／变异力／金币三格、渔具与工具两槽、图鉴。图鉴以小鱼图标网格展示已诞生鱼种（最多 44 种，完成度统计全部鱼种），未捕获的鱼种以灰色显示。
- 状态：沿用旧版「状态」「池子状态」「完整状态」三个指令，改为图片。出现概率由 `capture.spawn_odds` 计算，与实际刷鱼共用同一套权重，最多列出 40 种，按概率从高到低排列。
- 抽卡结果：重复物品堆叠，按稀有度从高到低排列，稀有度 4 及以上整卡浅色高亮；标题区显示总件数和种类数。

购买、装备／卸下、使用道具仍用旧版文字反馈。

## 族谱网页

`web/lineage.html` 是单文件页面，挂在 `/infinite-mutation-fishing/lineage/<令牌>`，数据来自 `/api/infinite-mutation-fishing/lineage/<令牌>`（公网经 nginx 转发到 `/web`）。令牌是群号加盐后 SHA-256 的前 16 位（`lineage.py`），链接里不出现群号；接口只返回鱼的数据、群友名片和取色结果，不返回任何 QQ 号。

页面以「水深」表示代数：越往下代数越大、水越深。选中一条鱼会点亮它到祖先的整条血统洋流，右侧（手机为底部抽屉）显示基因来源：鱼身、花纹分别来自哪位群友的头像，鱼鳍由亲代三色调和，并把鱼鳍颜色按 1/3、1/9… 的权重逐代拆解成「鱼鳍血统」。正在生成的新鱼显示为挂在亲代下的虚线鱼卵。字体走 jsDelivr 的霞鹜文楷屏幕阅读版网页字体，开启「减少动态效果」时关闭所有动画。

## 每日签到

每人每天（北京时间）一次，必定捕获一条鱼，不消耗强化剂次数，也不受强化剂、加成卡影响。

- 抽鱼权重 = 不含食料与 Fever 加成的基础刷新概率（同稀有度内仍按难度与活跃玩家平均渔力分配）× 该玩家用等级与装备渔力算出的捕获成功率。
- 若该玩家对这条鱼的亲缘档位不是 5%（即 1% 或 0%），权重乘 0.25。
- 金币、经验取鱼的基础收益 × 同一个 5～20 的整数倍数；变异贡献按正常公式（含变异力和 0.85～1.0 浮动）再乘 2～10 的整数倍数，仍受剩余刻度与单人 99% 上限约束，可以直接触发变异。
- 结果用捕鱼结算卡展示，标题为「签到成功」，右上角显示金币经验倍数。参数在 `capture-settings.json` 的 `sign_in`。

## 商店、装备与道具

配置位于 `data/items.json` 与 `data/gacha.json`。商店渔具价格 50/200/1000/5000，渔力 10/20/40/80、变异力 0；抽卡工具渔力与变异力均为 5/10/20/40/60。两个槽位分别装备一件，物品保留在背包，重复获得按数量堆叠、不自动折现。

商店只卖普通食料（5）和白银食料（50），黄金食料靠抽。三档食料持续 30/45/60 分钟，分别增加 R 权重 40 倍、R/SR 权重 60/100 倍、R/SR/SSR 权重 60/120/200 倍（均在原权重上增加）。每份都只计一次投饵；有现存效果时需「强制使用」覆盖，Fever 中无法使用食料。已移除直接扣金币的「投饵」。

强化剂分别增加 10/20/40 渔力，持续下 1/2/4 次有效捕鱼尝试，失败也消耗次数，无鱼或已经尝试过则不消耗。加成卡持续 20 分钟，成功金币、经验同时增加 25%/50%/100%，分别向下取整；失败仍为 1 经验。同类效果覆盖，不叠加；强化剂与加成卡可共存。

奖池只保留工具及三档食料、强化剂、加成卡。每类普通／白银／黄金消耗品的单项权重为 10/5/2，五件工具权重 4/2/1/0.5/0.2，总权重 58.7，抽取时归一化。无积分、荧光棒、工坊材料或保底。

## 出生难度、收益与自然刷新率

`scripts/fit-rewards.py` 对旧版两个鱼池分别按稀有度做线性回归：R 15 条、SR 66 条、SSR 35 条，残差均为 0。采用 `R=难度+10`、`SR=难度×2`、`SSR=难度×3`，金币与经验相同，非整数向下取整。新鱼难度为稀有度基础值 0/30/100 加两位贡献者平均等级；不会累加亲代难度。祖先鱼保持难度 0、收益 10。已诞生的旧鱼保留原数值；旧待生成任务如无历史等级快照，迁移时使用当时可读等级并标记来源。

每次符合条件的分钟刷新判定，各档自然总出率固定为 R=1%、SR=0.2%、SSR=0.05%。不存在鱼种的档位不出鱼，也不把概率转移给其他档。先判定是否出鱼，再按各档总出率选择稀有度，最后在该档内按难度相对活跃玩家渔力的权重抽取鱼种。每种鱼的档内权重为 `0.9 ** max(0, (难度-平均渔力)/15)`，不会因为某档鱼种增多而提高该档总出率。

| 食料 | R 总出率 | SR 总出率 | SSR 总出率 | 三档均有鱼时总出率 |
| --- | --- | --- | --- | --- |
| 无 | 1% | 0.2% | 0.05% | 1.25% |
| 普通 | 41% | 0.2% | 0.05% | 41.25% |
| 白银 | 61% | 20.2% | 0.05% | 81.25% |
| 黄金／Fever | 61% | 24.2% | 10.05% | 95.25% |

只有祖先鱼时仅应用 R 一列。存在鱼时不再刷，凌晨 1～8 点不刷，调度有最多 15 秒抖动。将来若总概率超过 100%，总出率封顶并按各档权重比例分配。

子代稀有度在满刻度时独立抽取并保存，当前 `mutation_weight` 为 R/SR/SSR=100/25/5，即约 76.92%/19.23%/3.85%；与自然刷新的 `spawn_probability` 分开配置，不受饵料、亲代稀有度和代数影响。

新变异完成当前使用文字通知，包括名称、稀有度、描述、难度及基础奖励；图片在该鱼实际刷新及捕获结算时展示。

## 刷鱼与捕鱼 WebP 卡片

`src/infinite_mutation_fishing/visuals.py` 提供两个函数，直接返回 WebP `bytes`：

- `render_spawn_card(fish)`：鱼群刷新卡，展示鱼图标、名字、稀有度与代数。
- `render_catch_card(fish, player_name=..., coins=..., experience=..., mutation_contribution=..., contribution_note=...)`：捕获结算卡，展示金币、经验、实际成功率（`success_rate`，百分数，保留两位小数）与实际变异贡献；`mutation_progress` 显示结算后的总变异百分比和进度条，触发变异的结算显示 100%（存档已重置为新轮 0%）；0% 时可说明关联限制、机会已用等原因。

`FishVisual(name, colors, rarity, rarity_color, generation)` 是展示数据；`colors` 顺序为身体、斑纹、鳍尾。稀有度名称和标识颜色由调用方传入，预览中的“稀有”与收益数字只是示例，不决定游戏概率和奖励。

贡献单位为百分比刻度点：传入 `5` 显示 `+5%`；支持最多三位小数。应传已经结算的实际增量，例如 97% 到 100% 传 `3`，不能传未经截断的名义贡献。函数不计算资格、不改存档、不发送消息。

使用 Pillow 直接绘制固定轮廓，内存缓存字体和按配色／大小生成的鱼图标，WebP 编码使用 `quality=85, method=1`。无浏览器、无 AI、无网络依赖。字体统一使用 LXGW WenKai，复用宿主 `src/static/poke/LXGWWenKai-Regular.ttf`；独立部署时可放到子仓 `assets/fonts/`，或通过 `MUTATION_FISHING_FONT` 指定文楷字体路径。QQ 异步处理器后续接入时可用以下方式，保持 WebP 字节不转 PNG：

```python
data = await asyncio.to_thread(render_spawn_card, fish)
message = UniMessage.image(raw=data, mimetype="image/webp", name="fish-spawn.webp")
```

以上仅构造消息，实际发送由游戏指令决定。当前已接入刷鱼定时任务和捕获结算；`render_spawn_card(..., fever=True)` 显示多人鱼群，默认普通鱼；`render_catch_card(..., success=False)` 展示失败与参与经验。

运行 `venv/bin/python src/infinite-mutation-fishing/scripts/preview-cards.py` 生成刷鱼、捕鱼、0% 贡献、商店、背包、面板和抽卡的 WebP 样例，以及 50 次重复绘制的耗时报告，输出目录为子仓 `previews/cards/`。耗时包含绘图及编码，不包含 QQ 上传发送；不同机器的结果会变化。
